# GitHub 可发现性与影响力优化

## 做了什么

这次把公开仓库当成一个会长期被搜索、被转发、被陌生人第一次打开的小产品来重新整理了一遍。

主要改了 README 的前半部分，让人一进来就能知道：这是一个中文 PDF 发票批量重命名工具，适合报销前整理电子发票、火车票和凭证。它会自动提取发票号码和金额，把文件复制到新的“已重命名”文件夹，并生成 `发票号码+姓名+金额元.pdf` 这种统一命名。

还新增了 `CHANGELOG.md`，准备用 `v0.1.0` 作为第一个公开版本。仓库元数据也会补上 Description、Topics 和 Release，让 GitHub 搜索、Google/Bing、AI 搜索更容易理解这个项目。

## 为什么做

原来的项目功能是有价值的，但公开传播时最大的问题是“别人不知道为什么要用它”。README 更像内部说明，GitHub About 也是空的，没有 Topics，也没有 Release。

对陌生用户来说，这会带来几个障碍：搜索不容易搜到，点进来以后价值不够快，项目看起来也不够完整。优化的目标不是堆关键词，而是让真正需要整理发票的人能更快发现、更快看懂、更愿意试用。

## 值得记住的决策、坑或技术点

仓库名 `batch-invoice-renamer` 不需要改。它短、清楚，英文搜索友好，也不会限制项目只服务中国发票场景。中文场景通过 Description、README 和 Topics 来补充更合适。

README 前部最重要的不是功能清单，而是“它替谁省了什么麻烦”。所以这次把“报销前整理发票”放在了靠前位置，并强调“不修改原始文件”，这是信任点。

Release 对这种小工具也很重要。哪怕没有打包成 exe，首个版本也能让项目看起来不是随手扔上来的脚本，而是有一个可引用、可回退、可传播的稳定版本。

没有强行加截图或 Demo，因为当前工具是本地文件处理脚本，最能说明价值的是输入输出文件名示例。后续如果要降低使用门槛，再考虑打包 Windows exe 或录一个简短动图。

## 一句话亮点

一个为中文报销场景做的小工具：选择发票文件夹，自动把 PDF 发票整理成“发票号码+姓名+金额元”的统一文件名。
