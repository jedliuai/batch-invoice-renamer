# 把发票脚本变成能直接点的工具

## 做了什么

这次把 GitHub 上原来的单次运行脚本接到了本地项目里，并做成了一个完整的桌面窗口。现在可以选择文件夹，也可以直接粘贴地址；姓名不再写死在代码里，发票号码、姓名、金额三项可以用上下按钮自由排列，还能换分隔符。

保存方式有两个：复制到自己指定的新文件夹，或者直接在原位置改名。默认仍然是复制。改名之前先扫描预览，表格能勾选、排除，也能手动修正号码和金额。补上了后台识别、进度、停止任务、金额合计、打开结果目录和导出 CSV 清单，常用设置也会记住。

启动入口依旧是一键重命名.bat，新增安装依赖.bat，第一次安装会建立项目自己的虚拟环境。README 和更新日志都按新的操作流程重写了，附上了使用合成数据的界面截图。最终 24 项自动化测试通过，也实际启动验证了 Windows 双击入口。

## 为什么做

原脚本已经能识别发票，但改姓名还得编辑 Python，命名顺序和输出位置也不能随手调整。每次整理报销都可能换人、换文件夹，真正缺的是一个把这些选项放在一起、先看结果再执行的入口。

## 值得记住的决策和坑

- 选择 Python 自带的 Tkinter 做本地窗口。这个场景直接操作本地文件夹最重要，不需要再带一套网页服务或 Node 依赖，发票也始终在本机处理。
- 把识别和文件操作拆进 invoice_core.py，窗口逻辑放在 invoice_app.py。原来的 rename_invoice.py 留作启动入口，原命令继续能用。
- “覆盖原发票”落实为“在原位置重命名”，只改文件名，PDF 字节不改。同名自动补序号，绝不为了改名覆盖另一张票。原位模式执行前确认，下次打开恢复默认复制模式。
- 预览和真正执行之间，磁盘状态可能变化。执行前检查源文件的大小和修改时间，复制目标用独占方式创建，避免预览后新出现的文件被覆盖；复制到一半出错会清理残留副本。
- 金额优先取价税合计和小写金额，支持千分位与负数。有多个零散金额、又没有明确总额标识时，宁可要求补填，也不随便选第一个。扫描件暂不做 OCR，界面说清原因并允许手填。
- 输出放在源目录内部时必须排除输出目录，不然下次扫描会把自己生成的结果再处理一遍。改了源目录或扫描范围，需要重新扫描。
- Tk 的 pack 布局如果先给表格分配空间，后面的修正按钮在小窗口里可能被截掉。把修正区域先预留在底部，再让表格使用剩余空间；设置侧保留滚动条。
- CSV 里的 20 位发票号码要防止 Excel 当数字截断精度，因此加文本前缀。文件名和说明也做了公式前缀保护。
- 自动测试使用临时目录和合成中文 PDF，覆盖文件保护和界面完整流程。额外拿本地三张实际样本核对了票面，识别金额为 147.00、12.20、2772.00 元，临时复制成功，原文件与副本 SHA-256 一致。实际样本与临时渲染已加入 Git 忽略规则。
- 当前没有一键撤销，也没有把程序打包成独立 exe。需要保留原始名字时用复制模式，原位处理前可以先导出预览清单。

## 一句话亮点

把只能跑一次的发票脚本，变成了一个能改姓名、调顺序、先预览再整理的桌面小工具，报销前再也不用挨个复制发票号改文件名。
